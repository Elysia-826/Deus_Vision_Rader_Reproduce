## 一、变更清单

### 1.1 阵容与槽位

| | 2026 | 2027 | 影响 |
|---|---|---|---|
| 地面机器人/侧 | 英雄+工程+步兵×2+哨兵=5 | **重装+步兵×2+哨兵=4** | 槽 10→8 |
| 装甲板 | 固定印刷数字 (1,2,3,4,S) | **点阵屏幕**（样式未发布） | 图案分类器阻塞 |
| 空中机器人标记 | 0x0305 含空中 | **只标地面机器人** | 0x0305 槽数待确认 |
| 多机通信 | 主要发给哨兵 | **可发给所有己方机器人** | 0x0301 扩展 |

### 1.2 场地与雷达

| | 2026 | 2027 | 影响 |
|---|---|---|---|
| 雷达基座高度 | 2.5m | **2.4m** | 相机视角变化 → 外参标定 |
| 场地新元素 | — | 制高点、隧道、机库、工作台 | 地标表 + 网格 mesh 重建 |
| 取消元素 | 飞坡、停机坪 | — | 地标表删除 |
| 功率限制 | — | **750W**（220V 市电） | 硬件预算 |

### 1.3 通信协议

| 命令字 | 2026 | 2027 | 状态 |
|---|---|---|---|
| 0x0305 | 48B（敌6+己6，含空中） | 槽数/格式待确认 | ⏳ 等协议 |
| 0x0301 | 机器人间通信 | 通信范围扩大 | 基本不变 |
| 0x0121 | 雷达自主决策 | 可能保留 | 待确认 |
| 0x020C/0x020E | 标记进度/雷达信息 | P 公式相同 | 大概率不变 |
| 0x0A01-0x0A06 | 信息波/干扰波 | 新增装甲受击信息 | 无线电组关注 |

### 1.4 P 公式（不变）

- 准确 <0.8m / 半准确 0.8-1.6m / 错误 ≥1.6m
- 连击 x 累进：+1.0/+0.5/-0.8
- 0.5s 中断 = 一次错误
- P≥100 → 15% 易伤 / P≥120 → 20% 易伤
- 双倍易伤：累计 1min → 1 次，上限 2 次

## 二、模型重训决策

### 2.1 必须重训（新场地 → 新视觉域）

| 模型 | 重训原因 | 重训方式 | 依赖 |
|---|---|---|---|
| **车 YOLO** | 新场地背景+新视角+新精细度 | 从 2026 checkpoint 精调（形状任务转移性好） | 新渲染序列 |
| **装甲 YOLO** | 点阵屏替代灯条 → red/blue/dead 分类可能失效 | **从零训练**（如果装甲视觉完全变了） | 点阵屏样式 |
| **图案分类器** | 点阵屏显示内容 ≠ 印刷数字 | **从零训练**（输入域完全变化） | 点阵屏样式 |
| **PnP 标定** | 新场地几何 + 新雷达高度 | 重新标定（6+ 地标） | 新场地 CAD |

### 2.2 不需要改

- stub 裁判 P 计分逻辑（公式不变）
- 跟踪器框架（级联匹配、身份投票、发布门）
- 裁判串口骨架（帧格式/CRC 不变，换命令字表）
- Docker 环境
- 海康拉流

### 2.3 正确的全链重训顺序（级联崩塌教训）

```
❌ 错误：单独训/换任一模型 → 下游因 ROI 域偏移而崩塌

✅ 正确：
  1. 新 Blender 场景 + 新雷达位姿 → 渲染训练序列
  2. 训车 YOLO（从 2026 checkpoint 精调）
  3. 用新车模型收割装甲训练数据（render_armor_crops.py）
  4. 训装甲 YOLO
  5. 用新装甲模型收割图案训练数据（render_pattern_crops.py）
  6. 训图案分类器（从零，因点阵屏是新域）
  7. 全部一起换入 → 基准回放验证
```

预计总耗时（5070 台式机）：
- 渲染 3 序列 × 200 帧 = ~30 分钟
- 训车 YOLO 20 epochs = ~3-5 小时
- 收割装甲 + 训装甲 = ~1 小时
- 收割图案 + 训图案 = ~1 小时
- 基准验证 = ~30 分钟
- **总计：~6-8 小时（一个完整训练日）**

### 2.4 雷达高度变化的影响

| 变化 | 对策 |
|---|---|
| 基座 2.4m（vs 2.5m） | 相机外参微调 → PnP 重新标定即可 |
| 场地更精细 → 背景纹理变化 | 训练数据域变化 → 全模型重训 |
| 新地标（制高点/隧道/机库） | PnP 标定利用新地标；可能的遮挡影响跟踪 |

## 六、2027 新功能遗漏分析（2026-10-18 深度审查规则手册后发现）

> 来源：用户提供的详细规则解析，对照现有代码逐条核实。

### 6.1 自适应装甲加固中心点（§5.2, p72-73）— **最高优先级**

2027 全新机制：雷达成为「装甲指挥节点」。

**机制**：
- 开赛后每 1 分钟全队获得 1 次可累积的加固机会
- 全队累计命中 ≥ 10 发弹丸后，由雷达向裁判系统发送指令消耗 1 次加固机会
- 选择/改变 1 个加固中心点：以中心点为圆心、面积 A 的圆形区域受弹伤害 **×0.5**
- 其余未加固区域 **×1.5**（惩罚更重）
- 可加固面积 A = 装甲板面积 × ρ²/(2+ρ²)，其中相对准确率 ρ = Λ己方/Λ对方、Λ = η/σ
- （η=命中率、σ=命中点散布中位半径）
- 每发弹丸击中位置 (x, y, 命中区域) 通过**雷达无线链路**（信息波）发送给攻击方

**雷达的软件任务**：
1. 实时接收并统计弹丸命中分布（来自信息波 0x0A05 或新命令字）
2. 计算中位散布 σ、命中率 η → 推导可加固面积 A
3. 决策最优加固中心点（优化问题：哪里×0.5 最有价值？）
4. 通过指定接口下发指令（≥10 发命中后才能触发）

**没有这个功能 = 全队装甲 ×1.5 vs 有这个功能 ×0.5——3 倍伤害差距。**

依赖：信息波解码（无线电组）+ 2027 通信协议（加固命令字格式）

### 6.2 哨兵→雷达数据接收（§3.2.3, p28）— **高优先级**

规则原文：「雷达只能接收**哨兵机器人**的数据」

- 哨兵把传感器数据（哨兵视角的敌方位置）发给雷达
- 雷达需要解析并与视觉检测融合——哨兵可能看到雷达看不到的区域
- 形成哨兵→雷达→全队 的**单向数据链闭环**
- 当前只有雷达→哨兵方向（`send_sentry_guidance`），缺少接收方向

**匹配代价接口已实现（2026-10-22）**：
- `CascadeMatchTracker(own_team=...)` + `set_ally_hints(positions)`——
  哨兵报的己方坐标进匈牙利代价：观测距盟友提示 <2m 时，进己方槽
  减罚（−0.45）、进敌方槽加罚（+0.9）。判定基准是 `slot.team` vs
  `own_team`（提示的阵营语义），不拿 `obs.team`（灯条）当判据——
  灯条远距 71% 误读率，正是这个提示要修的对象。
- 有单测锁死符号方向（敌我步兵贴脸几何，旧版符号反了时必红）。
- **剩余**：协议发布后把哨兵消息解析接到 `set_ally_hints`（一行
  调用 + own_team 从相机名/env 带入）。

依赖：2027 通信协议（哨兵→雷达消息格式）

### 6.3 定位模块离线联动（§5.1.5.4, p71）— **中优先级** → **✅ 已实现**

规则原文：
> 「若地面机器人定位模块离线：对方雷达对该机器人的标记**始终视为准确**；己方雷达对其标记始终视为错误。」

- 敌方定位模块掉线 = 我们对它发任何坐标都算准确 → 免费 P 到 150
- **雷达应优先标记可能定位模块离线的目标**（收益远高于普通目标）

**已实现并接进主循环（2026-10-22）**：
- `SendQualityTracker`：每帧记各敌方槽标记源的 CONFIRMED/LOST 占比
- `detect_offline_targets(mark_progress, quality)`：易伤位亮 +
  CONFIRMED 占比 <0.5（P≥100 需要持续准确流，外推占大头撑不起）
  → 判离线。0x020C 只有 1 bit/槽，P 攒分过程看不见，检测只能靠
  发送质量反推——但「易伤位亮 + 外推为主」这个组合只有离线判准能解释。
- `marks_from_publishes(priority_slots=...)`：离线槽放行 LOST 标记
  （怎么发都算准），TENTATIVE 仍拦（发错槽的标记无意义）。
- 自纠偏：误判时外推标记吃 ERROR → P 跌破 100 → 位灭 → 自动除名。
- 陈旧过滤联动：≥0.5s 生外推不发（P 经济学为负），离线优先槽例外。
- 真机实测前无法验证误报率——stub 基准里模块不模拟离线，检测
  在仿真里天然不触发，属预期。

依赖：仅依赖 0x020C（已实现）✅

### 6.4 压制状态下的标记策略调整（§4.3）— **低优先级**

- 0x020E bit3-4 告诉我们己方加密等级（已解析）
- 被压制时（对方加密等级 > 己方）：标记不产易伤——但小地图显示仍有价值
- 策略：被压制时仍发标记（小地图有用）但可降精度投入，省算力给加固决策
