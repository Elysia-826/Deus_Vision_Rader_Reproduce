# 裁判系统串口协议——雷达侧数据字典

> 依据《RoboMaster 2027 机甲大师高校系列赛通信协议》**V1.0.0（20261029）**。
> 本地留档：`refs/`（不进 git）。2026 V1.3.0 的 0x020E=1B / 0x0121=8B / 0x0003=16B 已作废。
> 对应实现：`referee/` 包。本文是协议要点 + 设计决策，不是协议全文。

## 1. 帧格式（全小端）

```
| SOF 0xA5 | data_length u16 | seq u8 | CRC8 u8 | cmd_id u16 | data[n] | CRC16 u16 |
```

- CRC8：poly `x⁸+x⁵+x⁴+1`（反射 0x8C），初值 `0xff`，只校验帧头前 4 字节。
- CRC16：poly `0x8408`（CRC-CCITT 反射），初值 `0xffff`，覆盖 帧头+cmd_id+data，小端写入帧尾。
- 常规链路：电源管理模块 **User 串口**，`115200` 8N1。雷达自身 ID：红 9 / 蓝 109。

## 2. 雷达相关命令字

### 上行（雷达 → 服务器）

| cmd_id | 载荷 | 频率 | 语义 |
|---|---|---|---|
| **0x0305** | **48B** = 24×u16 **cm** | ≤5Hz | 小地图标记。12 槽：敌方 重装/保留/步3/步4/保留/哨兵，己方同序。**(0,0)=该机器人不发送**。下标 1、4 无角色映射，保持不发。标签 `*2` 不进此命令。雷达 ID 红 9 / 蓝 109 |
| 0x0301 | 6B 头 + 内容（内容 ≤112B；表列 118B 是整段 data 上限，不是定长） | ≤30Hz（整个 cmd 共享） | 机器人交互数据外壳：子内容ID u16 + 发送者 u16 + 接收者 u16 + 内容 |
| └ 子内容 **0x0121** | **13B** | 触发式 | byte0=双倍易伤触发计数（**单调+1**，开局 0）；byte1=密钥指令（1=改己方密钥，2=提交破解的对方密钥）；byte2-7=6 位 ASCII 密钥；byte8=`armor_fortify_cmd`（独立单调计数，开局 0，**不与双倍计数混用**）；byte9-10 / 11-12=加固圆心 x/y **mm**。发送者=雷达自身 ID，接收者=**0x8080**。本仓暂不实现何时加固；默认后 5 字节为 0 |

### 下行（服务器 → 雷达）

| cmd_id | 载荷 | 频率 | 语义 |
|---|---|---|---|
| 0x0001 | 11B | 1Hz | 比赛状态：低 4bit 类型 / 高 4bit 阶段（0 未开始…4 比赛中 5 结算）+ 剩余时间 u16 + UNIX u64 |
| 0x0003 | **24B** | 3Hz | 血量：0 己方重装 HP；2 保留；4/6 己方步3/4 HP；8 **int16** 队伍伤害差；10 己方哨兵 HP；12 红前哨 HP；14 己方基地 HP；16 蓝前哨 HP；18 敌方基地 HP；20 己方控制；22 敌方控制。未上场/罚下 HP=0。**不驱动双倍或标记门** |
| **0x020C** | 2B | 1Hz | 标记进度掩码：bit0=敌方重装易伤（P≥100）；bit1、bit4 保留；bit2/3/5=步3/步4/哨兵；bit6=己方重装特殊标识（P≥50）；bit7、bit10 保留。槽序同 0x0305 |
| **0x020E** | **8B** | 1Hz | byte0：bit0-1=双倍机会数(0–2)；bit2=对方双倍生效中；bit3-4=己方加密等级；bit5=可否改密钥。byte1：bit0=装甲加固生效中；bit1-3=剩余加固次数。offset 2/4/6 **uint16** 加固圆 x/y/半径 **mm**。**拒收 1 字节旧帧** |

## 3. 标记计分规则（规则手册 5.6.6，决定发送策略）

- 误差分级：**准确 <0.8m**，半准确 0.8~1.6m，错误 ≥1.6m；**0.5s 无数据 = 一次"错误"**。
- P 连击：连续准确 `x` 每次 +1.0 累进（半准确 +0.5），连续 5Hz 100% 准确 **3 秒到 P=120**；错误/中断 `x` 归 -0.8 连扣。
- **发送策略结论**：没把握就不发（(0,0) 不扣进度）；错发比静默代价高得多。这是
  `marks_from_publishes` 默认只发 CONFIRMED、LOST 外推默认不发的原因。
- 双倍易伤：累计 1 分钟易伤 = 1 次机会，`trigger_double()` 消耗；上限 2 次/局。
- P≥100/120 → 敌车 15%/20% 易伤，且官方小地图直接显示**定位模块真实位置**。

## 4. 坐标系（0x020B 权威定义）

> 原点在**红方补给站附近场角**，+X 沿长边**向蓝方**，+Y 沿短边**向红方停机坪**，单位 cm（x∈[0,2800]，y∈[0,1500]）。

本仓场地系：中心原点，+x 蓝侧（与裁判 +X 同向 ✓），+y 指官方俯视图上方。
**未核对项**：官方俯视图上方是否=红方停机坪方向。若联调发现相反，把
`referee/commands.py` 的 `_OUR_PLUS_Y_IS_REFEREE_PLUS_Y` 翻成 `False`，一处改动全局生效。
两方共用同一裁判图，**上传不做红蓝镜像**（T-DT 代码里的蓝方镜像是他们内部显示用）。

## 5. 与无线电组的接口

信息波/干扰波（官方雷达无线链路，0x0A01~0x0A06，均 ≤10Hz）：**密钥提交走我们这条串口**——
无线电组解出干扰波密钥（0x0A06）后交给视觉侧，由 `verify_enemy_password()` 经 0x0121 上传。
对方密钥破解失败则我方加密等级被升（0x020E bit3-4 可见），**干扰波难度高的一方：对面标记再准也不产易伤**。

## 6. 已知开放项（联调清单）

1. **y 轴朝向**：见 §4，一个布尔常量。
2. **真机验证 (0,0) 边角语义**：位于红方补给站场角 (0,0) 的车会被当"未发送"——实际不会发生（车进不了那个角），但联调时确认。
3. **0x0121 加固**：协议已定 13B；本仓只占位后 5 字节为 0，不计算圆心、不发加固指令。
4. seq 回绕、断线重连后的 seq 语义协议未定义，按 0 起点自增处理。

## 8. RM2027 超级对抗赛规则增量（规则手册 V1.0.0，20261015）

> 依据：规则手册 V1.0.0（20261015）+ 通信协议 V1.0.0（20261029）。线格式已回填到 §2。

### 8.1 沿用（现有实现与基准继续有效）

- P 计算逻辑（新手册表 5-29）与 5.6.6 **逐字相同**，worked example 数值完全一致（5Hz 全准 3s 到 P=120）→ `referee/stub.py` 金标 `test_rulebook_example` 不变。
- P 阈值效果（表 5-30）：敌 [100,120)=15% 易伤、[120,150]=20% 易伤 + 小地图显示定位模块真实位置；己 [50,150] 仅显示。双倍易伤：工会 60s=1 次、30s 生效、≤2 次/局、**多台同时易伤不累加**——stub 取并集 ✓。
- 比赛流程阶段（3min/15s/5s/7min）不变；战场仍 28m×15m。
- 干扰波/密钥体系沿用（开局默认一级、三级难度、对面难度高→我标记不产易伤）；信息波内容清单不变；难度具体参数官方"后续发布"。

### 8.2 新增

1. **阵容/槽位**：英雄+工程合并为**重装机器人**（编号 1）；地面每方 4 台（重装×1、步兵×2[编号 3/4]、哨兵×1[编号 7]）。雷达只标地面机器人。0x0305 **仍 48B / 12 槽**，下标 1、4 保留不发；`ROLE_TO_INDEX` 已去掉 `"2"`，`"1"` 仍映射槽 0。
2. **自适应装甲（新手册 5.2）**：协议已把加固放进 0x0121 byte8–12 与 0x020E byte1+圆心 mm。本仓只占位（默认 0），**不实现何时加固、圆心怎么算**。弹着点走无线 0x0A05，本仓不做解调。
3. **场地元素**：新增制高点、机库平台、工作台；取消飞行区、停机坪、无线充电装置放置区（`scene/` 需一轮场地比对）。雷达基座（4.2.5）：平台 3.4×1.16m、高 ~2.4m、1.1m 围栏、220V 市电、官方 HDMI 显示器 1920×1080。
4. **人员**：新增指挥手/安全员，取消云台手/飞手。指挥手可干预哨兵（转发小地图标记等，与雷达上行无关）。

### 8.3 V2.2.0 已有、此前本笔记漏记（现补入）

- **定位模块离线（5.1.5.4）**：敌方定位模块离线 → 我对其标记**恒为"准确"**（白捡易伤/双倍进度）；己方离线 → 恒为"错误"（别浪费发弹）。无离线下行通道，需行为推断；stub/sim 可加 offline 开关做 A/B。
