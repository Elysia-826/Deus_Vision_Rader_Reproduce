# 裁判系统串口协议——雷达侧数据字典

> 依据《RoboMaster 2026 机甲大师高校系列赛通信协议》**V1.3.0（20260327）**。
> 本地留档：`refs/`（不进 git）。V1.2.0 的 0x0305 是 24B 旧版，**实现一律按 V1.3.0**。
> 对应实现：`referee/` 包。本文是协议要点 + 设计决策，不是协议全文。

## 1. 帧格式（全小端）

```
| SOF 0xA5 | data_length u16 | seq u8 | CRC8 u8 | cmd_id u16 | data[n] | CRC16 u16 |
```

- CRC8：poly `x⁸+x⁵+x⁴+1`（反射 0x8C），初值 `0xff`，只校验帧头前 4 字节。
- CRC16：poly `0x8408`（CRC-CCITT 反射），初值 `0xffff`，覆盖 帧头+cmd_id+data，小端写入帧尾。
- 常规链路：电源管理模块 **User 串口**，`115200` 8N1。雷达自身 ID：红 9 / 蓝 109。

## 2. 雷达相关命令字

### 上行（雷达 → 服务器）

| cmd_id | 载荷 | 频率 | 语义 |
|---|---|---|---|
| **0x0305** | **48B** = 24×u16 cm | ≤5Hz | 小地图标记数据。12 槽：敌方 hero/工程/步3/步4/空中/哨兵，己方同序。**(0,0)=该机器人不发送**。这是"雷达识别"计分的唯一通道 |
| 0x0301 | 6B 头 + 内容 | ≤30Hz（整个 cmd 共享） | 机器人交互数据外壳：子内容ID u16 + 发送者 u16 + 接收者 u16 + 内容 |
| └ 子内容 **0x0121** | 8B | 触发式 | 雷达自主决策：byte0=双倍易伤触发计数（**单调+1**，开局 0）；byte1=密钥指令（1=改己方密钥，2=提交破解的对方密钥）；byte2-7=6 位 ASCII 密钥。发送者=雷达自身 ID，接收者=**0x8080（裁判服务器）** |

### 下行（服务器 → 雷达）

| cmd_id | 载荷 | 频率 | 语义 |
|---|---|---|---|
| 0x0001 | 11B | 1Hz | 比赛状态：低 4bit 类型 / 高 4bit 阶段（0 未开始…4 比赛中 5 结算）+ 剩余时间 u16 + UNIX u64 |
| 0x0003 | 16B | 3Hz | **己方**血量：hero/工程/步3/步4/保留/哨兵/前哨站/基地（各 u16） |
| **0x020C** | 2B | 1Hz | 标记进度掩码：bit0-5=敌方六车易伤（P≥100），bit6-11=己方六车特殊标识（P≥50），敌方槽序同 0x0305 |
| **0x020E** | 1B | 1Hz | bit0-1=双倍易伤机会数(≤2)；bit2=对方触发中；bit3-4=己方加密等级(1-3，即对方干扰波难度)；bit5=当前可否改密钥 |

## 3. 标记计分规则（规则手册 5.6.6，决定发送策略）

- 误差分级：**准确 <0.8m**，半准确 0.8~1.6m，错误 ≥1.6m；**0.5s 无数据 = 一次"错误"**。
- P 连击：连续准确 `x` 每次 +1.0 累进（半准确 +0.5），连续 5Hz 100% 准确 **3 秒到 P=120**；错误/中断 `x` 归 -0.8 连扣。
- **发送策略结论**：没把握就不发（(0,0) 不扣进度）；错发比静默代价高得多。这是
  `marks_from_publishes` 默认只发 CONFIRMED、LOST 外推默认不发的原因。
- 双倍易伤：累计 1 分钟易伤 = 1 次机会，`trigger_double()` 消耗；上限 2 次/局。
- P≥100/120 → 敌车 15%/20% 易伤，且官方小地图直接显示**定位模块真实位置**。

## 4. 坐标系（0x020B 权威定义）

> 原点在**红方补给站附近场角**，+X 沿长边**向蓝方**，+Y 沿短边**向红方停机坪**，单位 cm（x∈[0,2800]，y∈[0,1500]）。

本仓场地系：中心原点，+x 蓝侧（与裁判 +X 同向 ✓），+y 指官方俯视图上方。
**未核对项**：官方俯视图上方是否=红方停机坪方向。若联调发现相反，把
`referee/commands.py` 的 `_OUR_PLUS_Y_IS_REFEREE_PLUS_Y` 翻成 `False`，一处改动全局生效。
两方共用同一裁判图，**上传不做红蓝镜像**（T-DT 代码里的蓝方镜像是他们内部显示用）。

## 5. 与无线电组的接口

信息波/干扰波（官方雷达无线链路，0x0A01~0x0A06，均 ≤10Hz）：**密钥提交走我们这条串口**——
无线电组解出干扰波密钥（0x0A06）后交给视觉侧，由 `verify_enemy_password()` 经 0x0121 上传。
对方密钥破解失败则我方加密等级被升（0x020E bit3-4 可见），**干扰波难度高的一方：对面标记再准也不产易伤**。

## 6. 已知开放项（联调清单）

1. **y 轴朝向**：见 §4，一个布尔常量。
2. **真机验证 (0,0) 边角语义**：位于红方补给站场角 (0,0) 的车会被当"未发送"——实际不会发生（车进不了那个角），但联调时确认。
3. **0x0301 子内容表**：V1.3.0 里 0x0121 子内容表标注"内容数据段长度 1"，但其详表（radar_cmd+password_cmd+password[6]）明确 8B——按详表实现；联调确认。
4. seq 回绕、断线重连后的 seq 语义协议未定义，按 0 起点自增处理。
